# 应用签名

Debug 和 Release 都使用仓库根目录 `.signing/newbv.keystore` 的固定密钥。
该目录已被 Git 忽略，私钥不能提交；请在仓库之外另存安全备份。
现有密钥的 alias 为 `androiddebugkey`，密钥库和条目密码均为 `android`。
密码不承担发布身份保护，必须保管好私钥文件本身。

本地构建前将现有密钥放到上述路径。缺少文件时签名任务失败，不会生成或回退到随机密钥。

## GitHub Actions

`mods` 推送及手动触发使用 `build-debug.yml`，同时构建和发布两种 APK。
工作流从仓库 Actions Secret `DEBUG_KEYSTORE_B64` 还原到相同路径。
密钥缺失或无效时，由 Android 构建工具终止构建。

在已登录 gh 的 PowerShell 中同步现有密钥（不输出密钥内容）：

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes((Join-Path $PWD '.signing/newbv.keystore'))) |
    gh secret set DEBUG_KEYSTORE_B64 --repo mz289/newBV
```

不要为了修复构建重新生成密钥。
Debug 与 Release 包名不同，更新时应保持同一变体。

## 旧版本限制

已发布的 r166、r167 使用了不同的 CI 临时签名，均不同于当前固定密钥。
旧签名私钥未保存，无法从 APK 恢复，因此这些版本无法通过新密钥原地覆盖升级。
固定签名解决后续版本之间的升级一致性，不能绕过 Android 对旧版本签名的校验。
